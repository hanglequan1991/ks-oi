## Acceptance criteria
1. AC1: `src/sync/writeHotel.ts` exports `buildHotelStatements(db, ctx): D1PreparedStatement[]` where `ctx = { tab: SheetTab; record: ParsedHotel; hotelId; slug: string; now: string; autoPublish: boolean; existingStatus: 'review'|'published'|'hidden'|null; hash: string }`. It does not execute anything.
2. AC2: city: `INSERT ... ON CONFLICT(slug) DO NOTHING` from `tab.fileName`; city slug = foldText with spaces to `-`; `name_vi` = fileName (STORY-14 AC1).
3. AC3: hotel: `INSERT ... ON CONFLICT(id) DO UPDATE` of name (tab name), `name_search` = foldText(name), stars, address, area, descriptions, source_file_id, source_gid, source_hash, synced_at. The slug comes from `ctx.slug` (generated by the caller, TASK-53) and is never updated on conflict. `rooms_synced_at` and `facilities_synced_at` set to `now`.
4. AC4: status policy (decision 2026-11-19: `sync_auto_publish` defaults to 'true'): a new hotel gets `published` when `autoPublish` is true, else `review`; an existing hotel keeps its status (never downgrades; a hotel the owner hid is never un-hidden by this builder; restore of sync-hidden hotels to `prior_status` is done by TASK-53, not here). Test through the fake D1 by executing the statements.
5. AC5: images: delete all rows of the hotel then insert `(hotel_id,url,position)` in sheet order; duplicates dropped keeping first.
6. AC6: facilities: delete rows with `source='sheet'` for the hotel; for each label, fold it and match against `facility_catalog.synonyms` (JSON array of folded strings) or `code`; matched codes insert with `source='sheet'`; unknown labels are not inserted and are returned in a second export `unmappedFacilities(db, labels): Promise<string[]>` so the caller can report them. Rows with `source` other than `sheet` are untouched.
7. AC7: running the statements twice gives identical table contents (idempotent).

## Dev notes
The facility_catalog is empty after migrations (no seed exists); tests insert their own catalog rows. Seeding the real catalog is not part of this story (see assumptions in the lead report).

- Implemented `buildHotelStatements` and `unmappedFacilities` in `src/sync/writeHotel.ts`. Facility matching is done in SQL (`INSERT OR IGNORE ... SELECT` joined on `facility_catalog`), so the builder stays synchronous.
- The hotel upsert also updates `city_slug` on conflict (not in the AC3 list), so a renamed city file moves its hotels. The city row is inserted earlier in the same batch.
- `unmappedFacilities` returns the verbatim label, first occurrence per folded form.
- `existingStatus` is not used in SQL: status is only written on insert, which keeps existing status.
- Tests: `test/sync/writeHotel.spec.ts`, 7 passing. Full unit suite: 56 files, 394 tests passing.

## Review
