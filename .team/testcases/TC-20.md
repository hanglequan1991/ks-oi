# TC-20: Clients over the rate limit are refused with 429; other clients and endpoints are unaffected

- id: TC-20
- story: [STORY-16](../stories/STORY-16.md)
- verifies: AC10
- status: todo
- rework count: 0
- automation test file: `sheet-rag/e2e/TC-20.e2e.ts`
- runs without Cloudflare credentials: yes (memory limiter; the real Cloudflare limiter is TC-24)

## Preconditions
- TASK-12 and TASK-14 done; Playwright installed (plain Node test, uses the Playwright `request` fixture).
- Harness (inline in the test file, no shared helper): a Node `http` server on port 0 that converts each request to a `Request` and calls `createApp(deps).fetch`. `mount` registers stub handlers for `/search`, `/chat`, `/api/suggest`, `/api/hotels` that increment a counter (they stand in for the AI service and the data layer). Default limits `RATE_LIMITS` (search 20, chat 20, suggest 120, data 60 per minute) are used, imported from `src/web/app.ts`; the real clock runs and all steps finish well inside one window.
- Client identity is set with the `CF-Connecting-IP` header.

## Steps
1. From IP A send 20 requests to `/search?q=hotel`; record statuses and the stub counter.
2. Send the 21st request from IP A.
3. From IP A request `/chat` (POST JSON `{"message":"hi"}`), `/api/suggest?q=ha` and `/api/hotels`.
4. From IP B request `/search?q=hotel`.
5. Send requests to `/api/hotels` and `/api/cities` from IP C until the 61st total.
6. Fallback: from a client without `CF-Connecting-IP` but with `X-Forwarded-For: 198.51.100.1, 10.0.0.1`, send 21 requests to `/search?q=x`.

## Expected results
1. Requests 1 to 20 return 200 and the stub counter is 20.
2. The 21st returns 429 with header `Retry-After` (60), `Content-Type: application/json` and body `{"error":"too_many_requests"}`; the stub counter stays 20 (the refused request never reaches the handler).
3. `/chat`, `/api/suggest` and `/api/hotels` from IP A still return 200 (separate counters per endpoint group).
4. IP B gets 200 (normal use of other clients is not affected).
5. The 61st data request gets 429 and `/api/hotels` and `/api/cities` share the `data` counter.
6. The 21st request is refused using the first `X-Forwarded-For` entry as the client key.
7. Chat is limited on its own: 21 chat requests from IP D give 429 on the 21st while `/search` for IP D is still 200.

## Test data
- IPs 203.0.113.1 (A), 203.0.113.2 (B), 203.0.113.3 (C), 203.0.113.4 (D); limits as above.
