# TC-22: Over-long chat and search input is refused before the AI service is called

- id: TC-22
- story: [STORY-16](../stories/STORY-16.md)
- verifies: AC13
- status: deferred
- rework count: 0
- automation test file: `sheet-rag/e2e/TC-22.e2e.ts`
- runs without Cloudflare credentials: yes (the stub handler is the stand-in for the AI call)

## Preconditions
- TASK-13 and TASK-14 done; Playwright installed (plain Node test, `request` fixture).
- Harness (inline in the test file, no shared helper): a Node `http` server on port 0 that converts each request to a `Request` and calls `createApp(deps).fetch`. `mount` registers stub handlers for `/search`, `/chat`, `/api/suggest`, `/api/hotels` that increment a counter (they stand in for the AI service and the data layer). Each stub handler increments a counter named `aiCalls`. Limits: `SEARCH_MAX_CHARS` 200, `CHAT_MAX_CHARS` 1000, default body cap 8192 bytes. Rate limits are generous (inject limiters with a high limit) so they do not interfere.

## Steps
1. `GET /search?q=` with 200 characters, then with 201 characters.
2. `POST /chat` JSON `{"message": <1000 chars>}`, then `<1001 chars>`.
3. `POST /chat` with the over-long text in the alternative fields `query`, `text` and `q`.
4. `POST /chat` with a `Content-Length` above 8192 bytes.
5. `GET /api/suggest?q=` with 201 characters.
6. Vietnamese text of 200 characters including combining diacritics, and 200 emoji, sent to `/search?q=`.
7. Edge: `POST /chat` with missing `message`, with `message: 123`, and with invalid JSON.
8. Over-limit input while the client is also rate limited (limit 1 injected).

## Expected results
1. 200 characters give 200 and `aiCalls` +1; 201 give 400 with `{"error":"input_too_long","field":"q","max":200}` and `aiCalls` unchanged.
2. 1000 characters give 200; 1001 give 400 with `field":"message"`, `max":1000` and no AI call. For an accepted request the handler can still read the whole JSON body.
3. Each alternative field over the limit gives 400 and no AI call.
4. 413 `{"error":"body_too_large"}`, no AI call.
5. Suggestions: 400, no handler call.
6. Length is counted in Unicode code points, so 200 code points pass and 201 are refused, for Vietnamese text and for emoji alike.
7. Missing field, non-string field and invalid JSON are passed on to the handler (no 400 from the guard; status is whatever the stub returns).
8. The rate limit refusal (429) happens first and the AI counter stays unchanged.

## Test data
- Generated strings of exact lengths; Vietnamese sample "Khách sạn gần biển" repeated and padded to 200 code points.
