## Preconditions
- TASK-15 is done (blocked until the owner commits the real `src/index.ts`) and the owner has deployed the Worker with the `DB`, assets and rate limit bindings.
- `LIVE_BASE_URL` is set to the deployed address. The test uses `test.skip(!process.env.LIVE_BASE_URL)`. Only read-only requests are made; the AI-calling routes are only sent over-long input (refused before any AI call).

## Steps
1. Open a Version 1 page at its normal address and at `/en/` in a browser; read `<html lang>`.
2. Click the toggle, reload, and open the normal address again.
3. Request `/lang.js` and `/app.css`.
4. Read response headers of the page, of a JSON endpoint and of a 404.
5. Send an over-long query to `/search?q=` (201 characters) and an over-long `message` (1001 characters) to `/chat`.
6. Check that `/bill` is not linked on any page.

## Expected results
1. Normal address is `lang="vi"`; `/en/` is `lang="en"`.
2. The choice is stored in `hd_lang` and the matching language version is shown after reload and return.
3. Both static files return 200 with the right content types and are served from the live site's own origin (so CSP `'self'` works).
4. All three carry `X-Robots-Tag: noindex, nofollow` and the five security headers (nosniff, referrer policy, HSTS, CSP, frame options).
5. Both requests are refused with 400, before the AI service is used.
6. No page links to `/bill`.

## Test data
- `LIVE_BASE_URL`; generated over-long strings.
