# TC-27: Hotel list rejects invalid filters and caps the page size at 50

- id: TC-27
- story: [STORY-15](../stories/STORY-15.md)
- verifies: AC3
- status: todo
- rework count: 0
- automation test file: `sheet-rag/e2e/TC-27.e2e.ts`
- runs without Cloudflare credentials: yes (Node HTTP server around `createApp` + `mountApi`, fake D1, real migrations)

## Preconditions
- TASK-14, TASK-16, TASK-18 to TASK-25 done; Playwright installed (uses the Playwright `request` fixture, no browser page).
- Harness (inline in the test file, no shared helper): fresh fake D1 from `test/fakes`, `applyMigrations`, `seedApiSample` (TASK-16); a Node `http` server on port 0 that converts each request to a `Request` and calls `createApp({ getSettings, mount: mountApi({ db, getSettings }) }).fetch` with the real `getSettings` from `src/db/settings.ts`. Each test file builds its own database and server, so files can run in parallel.
- Each request sets its own `CF-Connecting-IP` (a unique address per test) so the `data` limit (60 per minute) is never reached by accident.
- The database also has `seedManyPublished(db, 60)` applied.

## Steps
1. `GET /api/hotels?limit=500`, `?limit=51`, `?limit=50`, `?limit=1`.
2. Send each invalid request: `?limit=abc`, `?limit=0`, `?limit=-5`, `?page=0`, `?page=abc`, `?stars=9`, `?stars=0`, `?stars=x`, `?sort=zzz`, `?city=Da%20Nang`, `?city=%27%3BDROP%20TABLE%20hotels`, `?facility=POOL%20%25`, `?lang=fr`.
3. Send an over-long `q` (500 characters) and a `q` with search syntax (`%25`, `_`, `"*"`, `a OR b`).
4. Count the rows in `hotels` through the fake D1 afterwards.

## Expected results
1. `limit=500` and `limit=51` return 200 with `limit` 50 and 50 items (capped, not rejected); `limit=50` gives 50; `limit=1` gives 1 item and `totalPages` 63.
2. Every invalid request returns 400 with JSON `{"error":{"code":"invalid_param","message":...}}`; the message names the offending parameter (limit, page, stars, sort, city, facility, lang). No 500, no stack trace, no SQL text in the body. `limit=0` and `limit=-5` may instead be capped or rejected: qa asserts whichever TASK-19 documents and records it in QA notes.
3. The long `q` gives 400 or a safe 200; search-syntax text gives 200 with no error and no `LIKE` wildcard effect (`q=%25` and `q=_` do not match every hotel).
4. The `hotels` row count is unchanged (65 rows).

## Test data
- Parameters as listed; 63 published hotels.
