# TC-31: A changed fee setting changes prices at once; out-of-range fee is clamped and a non-number falls back to 10

- id: TC-31
- story: [STORY-15](../stories/STORY-15.md)
- verifies: AC9
- status: todo
- rework count: 0
- automation test file: `sheet-rag/e2e/TC-31.e2e.ts`
- runs without Cloudflare credentials: yes (Node HTTP server around `createApp` + `mountApi`, fake D1, real migrations)

## Preconditions
- TASK-14, TASK-16, TASK-18 to TASK-25 done; Playwright installed (uses the Playwright `request` fixture, no browser page).
- Harness (inline in the test file, no shared helper): fresh fake D1 from `test/fakes`, `applyMigrations`, `seedApiSample` (TASK-16); a Node `http` server on port 0 that converts each request to a `Request` and calls `createApp({ getSettings, mount: mountApi({ db, getSettings }) }).fetch` with the real `getSettings` from `src/db/settings.ts`. Each test file builds its own database and server, so files can run in parallel.
- Each request sets its own `CF-Connecting-IP` (a unique address per test) so the `data` limit (60 per minute) is never reached by accident.
- The test changes only `settings.service_fee_percent` with SQL on the fake D1 and restores 10 at the end (the test owns its database, so no other test is affected).

## Steps
For each value below, run `UPDATE settings SET value = '<v>' WHERE key = 'service_fee_percent'`, then request `/api/hotels/mong-hotel` (Deluxe) and `/api/config` straight away (no wait, no restart):
1. v = `10` (baseline).
2. v = `20`.
3. v = `0`.
4. v = `100`.
5. v = `150` and v = `-5`.
6. v = `abc`, v = empty string, v = `10%`.
7. v = `12.5`.

## Expected results
1. Deluxe 1375000; config `serviceFeePercent` 10.
2. Deluxe 1500000; config 20 (new value on the very next request).
3. Deluxe 1250000 (no fee); config 0.
4. Deluxe 2500000; config 100.
5. 150 acts as 100 (2500000); -5 acts as 0 (1250000). Config shows the clamped value.
6. Falls back to 10: Deluxe 1375000, config 10, and no 500.
7. The test asserts the behaviour TASK-5 documents (accepted as 12.5 with rounding to 1,000: 1,406,250 becomes 1406000, or rounded to a whole percent); qa records which in QA notes.
8. After every step the status is 200 (a bad setting never breaks the API).

## Test data
- Deluxe base 1250000 only as the expectation input (never read from a response).
