## Preconditions
- TASK-14, TASK-16, TASK-18 to TASK-25 done; Playwright installed (uses the Playwright `request` fixture, no browser page).
- Harness (inline in the test file, no shared helper): fresh fake D1 from `test/fakes`, `applyMigrations`, `seedApiSample` (TASK-16); a Node `http` server on port 0 that converts each request to a `Request` and calls `createApp({ getSettings, mount: mountApi({ db, getSettings }) }).fetch` with the real `getSettings` from `src/db/settings.ts`. Each test file builds its own database and server, so files can run in parallel.
- Each request sets its own `CF-Connecting-IP` (a unique address per test) so the `data` limit (60 per minute) is never reached by accident.
- `seedManyPublished(db, 60)` applied for the limit checks.

## Steps
1. `GET /api/suggest?q=mo`, `?q=M%E1%BB%99ng` (Mộng), `?q=MONG`, `?q=m`.
2. `GET /api/suggest?q=ong` (a substring that is not a prefix) and `?q=hotel`.
3. `GET /api/suggest?q=bulk`, `?q=bulk&limit=10`, `?q=bulk&limit=1`.
4. `GET /api/suggest?q=mong&lang=en`.
5. `GET /api/suggest?q=<60 characters>` (exactly 60).
6. `GET /api/suggest?q=mong` and check that review and hidden hotels are absent.
7. Read `Cache-Control`.

## Expected results
1. Each of `mo`, `Mộng`, `MONG` returns `[{"slug":"mong-hotel","name":"Mộng Hotel","city":"Đà Nẵng"}]` and nothing else. `q=m` (1 character) is accepted and returns the same item.
2. `ong` and `hotel` return empty `items` (prefix only, so "Mộng Hotel" does not match "hotel").
3. `q=bulk` returns 8 items (default), `limit=10` returns 10, `limit=1` returns 1.
4. City is `Da Nang` with `lang=en`.
5. Exactly 60 characters is accepted (200).
6. `Mộng Review` and `Mộng Hidden` are never in the results.
7. 200 responses carry `Cache-Control: public, max-age=30`. Each item has only the keys `slug`, `name`, `city` (no price, no id).

## Test data
- Fixture hotels; `bulk-1..bulk-60` named `Bulk <i>`.
