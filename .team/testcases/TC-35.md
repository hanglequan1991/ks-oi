# TC-35: Suggest endpoint rejects bad input and handles hostile text safely

- id: TC-35
- story: [STORY-15](../stories/STORY-15.md)
- verifies: AC13
- status: deferred
- rework count: 0
- automation test file: `sheet-rag/e2e/TC-35.e2e.ts`
- runs without Cloudflare credentials: yes (Node HTTP server around `createApp` + `mountApi`, fake D1, real migrations)

## Preconditions
- TASK-14, TASK-16, TASK-18 to TASK-25 done; Playwright installed (uses the Playwright `request` fixture, no browser page).
- Harness (inline in the test file, no shared helper): fresh fake D1 from `test/fakes`, `applyMigrations`, `seedApiSample` (TASK-16); a Node `http` server on port 0 that converts each request to a `Request` and calls `createApp({ getSettings, mount: mountApi({ db, getSettings }) }).fetch` with the real `getSettings` from `src/db/settings.ts`. Each test file builds its own database and server, so files can run in parallel.
- Each request sets its own `CF-Connecting-IP` (a unique address per test) so the `data` limit (60 per minute) is never reached by accident.

## Steps
1. Invalid length: `/api/suggest` (no q), `?q=`, `?q=%20%20` (blank), and a 61-character `q`.
2. Invalid limit: `?q=mo&limit=0`, `?q=mo&limit=11`, `?q=mo&limit=abc`, `?q=mo&limit=-1`.
3. Hostile text: `?q=%25` (%), `?q=_`, `?q=%22*%22`, `?q=a%20OR%20b`, `?q=mo%20NEAR%20x`, `?q=%27%3B%20DROP%20TABLE%20hotels%3B--`, `?q=%5C` (backslash), `?q=%00`, `?q=%F0%9F%98%80` (emoji).
4. Count rows in `hotels` and `settings` afterwards.

## Expected results
1. 400 JSON `{"error":{"code":"invalid_q","message":...}}` each time; no database query is run (the test may spy on the fake D1 prepare calls).
2. 400 `invalid_param` (or `invalid_q` as TASK-19 defines for limit); message names `limit`.
3. Each returns 200 with empty `items` (or only genuine prefix matches) and no 500. `%` and `_` do not act as wildcards (they do not match every hotel).
4. Row counts unchanged (5 hotels, same settings).
