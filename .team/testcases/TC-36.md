# TC-36: Public config returns disclaimers, fee note flag and fee percent, and no contact data

- id: TC-36
- story: [STORY-15](../stories/STORY-15.md)
- verifies: AC14
- status: deferred

- automation test file: `sheet-rag/e2e/TC-36.e2e.ts`
- runs without Cloudflare credentials: yes (Node HTTP server around `createApp` + `mountApi`, fake D1, real migrations)

## Preconditions
- TASK-14, TASK-16, TASK-18 to TASK-25 done; Playwright installed (uses the Playwright `request` fixture, no browser page).
- Harness (inline in the test file, no shared helper): fresh fake D1 from `test/fakes`, `applyMigrations`, `seedApiSample` (TASK-16); a Node `http` server on port 0 that converts each request to a `Request` and calls `createApp({ getSettings, mount: mountApi({ db, getSettings }) }).fetch` with the real `getSettings` from `src/db/settings.ts`. Each test file builds its own database and server, so files can run in parallel.
- Each request sets its own `CF-Connecting-IP` (a unique address per test) so the `data` limit (60 per minute) is never reached by accident.
- The database also gets contact-like rows added by the test (`phone`, `zalo_link` keys with `0901234567` and `https://zalo.me/123`), to prove they are not exposed.

## Steps
1. `GET /api/config` on the seeded settings.
2. Walk all keys and values of the JSON recursively.
3. Update the fee to 12 and `show_fee_note` to `false`; request again.
4. Insert the extra phone and Zalo rows in `settings`; request again.

## Expected results
1. 200 with `disclaimer.vi` and `disclaimer.en` equal to the TASK-3 seeded texts, `showFeeNote` true, `serviceFeePercent` 10, `languages` `['vi','en']`; `Cache-Control: public, max-age=60`.
2. No key contains `phone`, `zalo`, `tel` or `contact` (case-insensitive); no value matches a phone number pattern (`\d{9,11}`) or contains `zalo.me`.
3. Shows 12 and `false`.
4. The response is unchanged by the extra rows: no other settings key is leaked, only the five fields above.

## Test data
- Settings keys from TASK-3.
