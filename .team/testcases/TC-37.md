# TC-37: No base price (or base-price field) ever appears in any API response

- id: TC-37
- story: [STORY-15](../stories/STORY-15.md)
- verifies: AC7
- status: deferred
- rework count: 0
- automation test file: `sheet-rag/e2e/TC-37.e2e.ts`
- runs without Cloudflare credentials: yes (Node HTTP server around `createApp` + `mountApi`, fake D1, real migrations)

## Preconditions
- TASK-14, TASK-16, TASK-18 to TASK-25 done; Playwright installed (uses the Playwright `request` fixture, no browser page).
- Harness (inline in the test file, no shared helper): fresh fake D1 from `test/fakes`, `applyMigrations`, `seedApiSample` (TASK-16); a Node `http` server on port 0 that converts each request to a `Request` and calls `createApp({ getSettings, mount: mountApi({ db, getSettings }) }).fetch` with the real `getSettings` from `src/db/settings.ts`. Each test file builds its own database and server, so files can run in parallel.
- Each request sets its own `CF-Connecting-IP` (a unique address per test) so the `data` limit (60 per minute) is never reached by accident.
- `seedManyPublished(db, 60)` applied. Because the sweep makes more than 60 requests, the test uses a different `CF-Connecting-IP` every 40 requests.

## Steps
Collect the raw response text (status line ignored, headers and body both) of every request below, at fee 10 and again at fee 0 (at fee 0 the final price equals the base price, so the test also checks the price appears only inside the `price` field):
1. `/api/hotels`, `?page=2&limit=50`, `?city=da-nang`, `?stars=5`, `?facility=pool`, `?q=mong`, `?limit=500`, and the 400 error responses of TC-27.
2. `/api/hotels/<slug>` and `?lang=en` for `mong-hotel`, `sao-hotel`, `dong-do-hotel`, plus the 404 for `mong-review`, `mong-hidden`, `khong-co`.
3. `/api/cities` (vi, en), `/api/suggest?q=mo`, `?q=bulk`, `/api/config`.
4. Parse every JSON body and walk all keys recursively.
5. Make the sweep also on the 500 error path: make `getSettings` reject (inject a failing settings function) and read the error body.

## Expected results
1. No response text (headers included) contains any string of `SAMPLE_BASE_PRICE_STRINGS` (`1250000`, `980000`, `1,250,000`, `980,000`, and every other seeded base price, including the non-published hotels' 555000 and 444000) at fee 10.
2. No key in any JSON body, at any depth, is named (case-insensitive) `base_price`, `basePrice`, `min_base_price`, `minBasePrice`, `price_base` or contains the text `base` together with `price`.
3. At fee 0 the price value equals the base value, therefore the only allowed place for those numbers is `price.amount`: the test asserts that for fee 0 every match of a base-price string sits under a key named `amount` inside a `price` object and nowhere else (no `basePrice`, no `originalPrice`, no `was`, no formatted copy such as `1.250.000`).
4. The 400, 404 and 500 bodies contain none of the strings, no SQL, no column name `base_price` and no stack trace.
5. The old hotel rows are still stored with the base price in the database (the test reads one `base_price` with SQL to prove the check is not vacuous).

## Test data
- `SAMPLE_BASE_PRICE_STRINGS` from `test/fixtures/apiSample.ts`; extra variants built by the test: `1.250.000`, `1 250 000`, `1250000.0`.
