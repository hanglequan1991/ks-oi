# TC-38: Only read endpoints exist; non-published hotels leak nowhere

- id: TC-38
- story: [STORY-15](../stories/STORY-15.md)
- verifies: AC1, AC5, AC9
- status: todo
- rework count: 0
- automation test file: `sheet-rag/e2e/TC-38.e2e.ts`
- runs without Cloudflare credentials: yes (Node HTTP server around `createApp` + `mountApi`, fake D1, real migrations)

## Preconditions
- TASK-14, TASK-16, TASK-18 to TASK-25 done; Playwright installed (uses the Playwright `request` fixture, no browser page).
- Harness (inline in the test file, no shared helper): fresh fake D1 from `test/fakes`, `applyMigrations`, `seedApiSample` (TASK-16); a Node `http` server on port 0 that converts each request to a `Request` and calls `createApp({ getSettings, mount: mountApi({ db, getSettings }) }).fetch` with the real `getSettings` from `src/db/settings.ts`. Each test file builds its own database and server, so files can run in parallel.
- Each request sets its own `CF-Connecting-IP` (a unique address per test) so the `data` limit (60 per minute) is never reached by accident.
- `seedManyPublished(db, 60)` applied.

## Steps
1. Send `POST`, `PUT`, `PATCH` and `DELETE` (with a small JSON body) to `/api/hotels`, `/api/hotels/mong-hotel`, `/api/cities`, `/api/suggest?q=mo`, `/api/config`.
2. Count rows and read the values of `hotels`, `rooms`, `settings` before and after step 1.
3. Run the read sweep (list pages, details, cities, suggest, config, `lang` vi and en) and collect all bodies.
4. Check security headers on one 200 and one 404: `X-Robots-Tag`, and the five security headers from STORY-16.
5. Send 61 `GET /api/hotels` from one IP, then one more from another IP.

## Expected results
1. Every write method returns 404 or 405, never 200 or 2xx.
2. The database is identical before and after (no row added, changed or removed).
3. No body of the read sweep mentions `mong-review`, `mong-hidden`, `Mộng Review` or `Mộng Hidden`, and the `total` of the list never counts them.
4. `X-Robots-Tag: noindex, nofollow` and the five security headers are present (STORY-16 guards still wrap the API).
5. The 61st request from the first IP gets 429 `{"error":"too_many_requests"}` and does not reach the route; the other IP gets 200.

## Test data
- Fixture hotels; limit 60 per minute for the `data` group.
