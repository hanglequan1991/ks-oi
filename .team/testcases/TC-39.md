# TC-39: LIVE - the deployed Worker serves the hotel API with final prices only

- id: TC-39
- story: [STORY-15](../stories/STORY-15.md)
- verifies: AC1, AC5, AC7, AC11, AC14
- status: blocked (needs live deployment; owner)
- rework count: 0
- automation test file: `sheet-rag/e2e/TC-39.e2e.ts`
- runs without Cloudflare credentials: no (needs the deployed Worker with the real D1 database; skipped when `LIVE_BASE_URL` is not set)

## Preconditions
- TASK-15 is done (`mountApi` wired into the real Worker entry), the owner has applied the migrations to the real D1 and has loaded data (STORY-14) or the sample data. Read-only test: it only sends GET requests and writes nothing.
- `LIVE_BASE_URL` is set; optional `LIVE_BASE_PRICE_STRINGS` (comma-separated base prices known to the owner from the sheet) for the price check. Stay below the data limit (at most 30 requests, no loop).

## Steps
1. `GET /api/config`, `/api/cities`, `/api/hotels?limit=5`.
2. Take the first hotel slug from the list and `GET /api/hotels/<slug>`.
3. `GET /api/hotels/zz-does-not-exist-404` and `/api/suggest?q=a`.
4. Check the response headers and, if `LIVE_BASE_PRICE_STRINGS` is set, search every body for those strings.
5. `POST /api/hotels` with an empty body.

## Expected results
1. 200 JSON; config has no phone or Zalo data; the list returns at most 5 published hotels with `price` null or an object with `VND` and `night`.
2. Detail 200 with rooms whose prices are final prices; no key named like `base_price`.
3. 404 `not_found`; suggest returns 200 with at most 8 items of `slug`, `name`, `city`.
4. `X-Robots-Tag: noindex, nofollow` and the security headers are present; none of the owner's base price strings appears in any body.
5. 404 or 405.
6. The page `/` and the existing `/search` route are unchanged (STORY-12): `/` still returns 200.

## Test data
- The owner's real data; no fixed hotel names are assumed.
