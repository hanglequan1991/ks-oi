Hotel Dictionary: Implementation Plan

A bilingual (Vietnamese default, English) website that lists hotels, locations, images, facilities, furniture, building details and rooms. Data comes from the Google Sheets already indexed by sheet-rag, optionally refreshed with room details and hotel utilities from mytour.vn through a Cloudflare Browser Run job. Prices shown to guests are the sheet base price plus a configurable service fee.

2. Architecture

Google Sheets (Drive folder)→ Sync worker (cron + queue)→ Staging & validation→ D1 database→ Website Worker + pages
mytour.vn→ Browser Run /crawl job→ Match & review queue→ updates room details and utilities in D1
Same sync worker→ Vectorize (existing)→ /chat and /search
  • One Worker, several entry points: fetch (website pages and API), scheduled (cron), queue (sync steps). The deployed sheet-rag already uses this shape.
  • Static pages are served from the same Worker through an assets binding. No separate hosting.
  • Price calculation happens in the API. The browser never receives the base price.

3. Data model (D1 sketch)

CREATE TABLE hotels (
  id TEXT PRIMARY KEY,              -- hash of fileId + gid
  city TEXT NOT NULL,               -- from the sheet file name
  name TEXT NOT NULL,               -- from the tab name
  stars INTEGER, address TEXT, description TEXT,
  lat REAL, lng REAL,
  status TEXT NOT NULL DEFAULT 'review',   -- review | published | hidden
  source_file_id TEXT, source_gid TEXT, source_hash TEXT, synced_at TEXT
);
CREATE TABLE hotel_facilities (hotel_id TEXT, category TEXT, label TEXT);  -- facility | furniture | building
CREATE TABLE hotel_images (hotel_id TEXT, url TEXT, position INTEGER);
CREATE TABLE rooms (id TEXT PRIMARY KEY, hotel_id TEXT, type TEXT, furniture TEXT,
                    description TEXT, bed_type TEXT, size_m2 REAL, view TEXT,
                    source TEXT,            -- sheet | mytour
                    sheet_room_id TEXT,     -- the sheet room that owns price and booking rules
                    max_guests INTEGER, base_price INTEGER);
CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT);   -- service_fee_percent, show_fee_note
CREATE TABLE overrides (hotel_id TEXT, field TEXT, value TEXT);
CREATE TABLE mytour_staging (url TEXT PRIMARY KEY, city TEXT, name TEXT, address TEXT,
                             stars INTEGER, facilities TEXT, fetched_at TEXT);
CREATE TABLE hotel_source_map (hotel_id TEXT, source TEXT, source_id TEXT, score REAL,
                               status TEXT, matched_at TEXT);   -- auto | confirmed | rejected
CREATE TABLE booking_rules (id TEXT PRIMARY KEY, hotel_id TEXT NOT NULL,
                            room_id TEXT,                  -- NULL = hotel-level rule
                            raw_text TEXT NOT NULL,        -- verbatim from the sheet
                            checkin_time TEXT, checkout_time TEXT, cancellation TEXT, deposit TEXT,
                            children_policy TEXT, pets TEXT, smoking TEXT, id_required TEXT,
                            payment_methods TEXT, min_stay TEXT, surcharges TEXT,
                            status TEXT DEFAULT 'review',  -- review | confirmed
                            synced_at TEXT);
CREATE TABLE room_type_map (room_id TEXT, source TEXT, source_room_name TEXT,
                            score REAL, status TEXT);      -- auto | confirmed | rejected
CREATE TABLE field_sources (hotel_id TEXT, entity TEXT, field TEXT, source TEXT,
                            source_url TEXT, fetched_at TEXT);

Add an FTS5 index on hotel name, address and city for dictionary-style search.

4. Phases

Size: S small, M medium, L large. Phases 1 to 4 are independent of Mytour.

Phase 0 Prerequisites and checks Size S · blocks everything
  • Recover the deployed sheet-rag source into the repo. The committed src/index.ts is an old prototype; deploying it would overwrite production.
  • Confirm the Vectorize index dimension (bge-m3 is 1024) and the actual sheet layouts: get about 20 rows from two tabs in different cities.
  • Fill the TODO placeholders in .team/config.md (build, tests, e2e, test folders). The team stops on placeholders.
  • Read mytour.vn robots.txt and terms, and get a legal opinion. Needs the host allowed in the session network.

Done when: source is in the repo and builds, config has no TODO, sample sheets reviewed, Mytour go/no-go recorded in .team/decision.md.

Phase 1 D1 schema and settings Size S · needs Phase 0
  • Create the D1 database and a migration for the tables in section 3.
  • Seed settings: service_fee_percent = 10, show_fee_note = true.
  • Add D1 and assets bindings to wrangler.jsonc; run wrangler types.

Done when: migration applies cleanly on a fresh database and a test reads the settings.

Phase 2 Sheet to D1 extraction Size L · the main risk
  • Extend the existing syncTab: after the CSV is fetched and the hash differs, extract a structured record and upsert it into D1. Keep the Vectorize step.
  • Hybrid extraction: a parser for tabular parts (rooms, prices); an LLM with a fixed JSON schema for free text (description, facilities, furniture, building). Image URLs are taken by pattern, never by the model.
  • Validation: price numeric, stars 1 to 5, URLs start with https. Failures set status = review and stay off the public site.
  • Apply overrides after every sync so manual corrections survive.
  • Booking rules (the most important data): store the sheet text verbatim at hotel level and at room level in booking_rules. Extract the structured fields (check-in and check-out times, cancellation, deposit, children and extra bed, pets, smoking, ID, payment, minimum stay, surcharges) only as a convenience, and keep them in review until a person confirms. Never rewrite or summarise the text.
  • Prices, descriptions and image links come from the sheet, never from Mytour.
  • Extend dropTab to hide or remove the hotel when its tab disappears.
  • Replace child rows (facilities, images, rooms) in one batch per hotel, keyed by the stable hotel id.

Done when: a forced reindex of sample sheets fills D1; rerunning changes nothing; an edited tab updates only that hotel; a deleted tab hides it.

  • Add CORS only if the pages are served from another domain, and rate limiting, because /search and /chat currently call a large model without limits.
  • Cache list responses briefly; invalidate after a sync.

Done when: unit tests cover the fee formula, filters and unpublished hotels never appearing.

Phase 4 Website pages Size M · needs Phase 3
  • Pages from the approved mockup: directory (home), hotel detail, mobile layout.
  • Language: vi by default; the VI/EN toggle writes hd_lang to localStorage inside try/catch, and reads it on load.
  • Disclaimer on every hotel card, every room row and the price panel, in the chosen language.
  • Booking rules shown verbatim at hotel level and under each room, with the sheet sync date. If a rule is missing, show "Please call to confirm", never a default.
  • Server-rendered or pre-rendered hotel pages with titles and descriptions for search engines.
  • Accessibility basics: labels, focus order, 44 px touch targets, text contrast.

Done when: an e2e test loads the home page in Vietnamese, switches to English, reloads and still sees English, and finds the disclaimer on every card.

Phase 4b Billing page (/bill) Size M · needs Phases 3 and 4

A public page where a visitor builds a bill across several hotels and rooms. The approved mockup is boards 4 to 6 of the design canvas (desktop, mobile, print).

  • Access: public at /bill and /en/bill; not linked anywhere on the site, not in sitemap.xml or robots.txt; noindex.
  • Grid: columns #, Hotel, Room, Night, Pricing, Total. Under each row a Note box (up to 500 characters). The note label is just "NOTE" ("GHI CHÚ"), without a row number, in the index column; the note box lines up with the grid (left edge with Hotel, right edge with Total).
  • Hotel and Room: autocomplete dropdowns (type to search, accents optional). Room options come from the selected hotel. Both can also be typed as free text.
  • Night: whole number 1 to 365. Pricing: VND with thousand separators, default is the room's final price including the service fee, editable, with an "edited" marker and a reset action. Total: Night x Pricing, plus a grand total.
  • Rows can be added (up to 30), removed (at least one stays) and cleared. Changing the hotel clears the room.
  • Draft: kept in the visitor's browser (localStorage, key hd_bill_v1) with a Clear button. Nothing is stored on the server, and notes never leave the browser.
  • Print / Save PDF: browser print with a dedicated print layout (no controls, notes shown, grand total, fee note, disclaimer, contact phone). No server-side PDF.
  • Disclaimer and fee note appear under the grid and on the printed bill; the contact phone comes from the admin configuration.
  • Language: follows the site language (Vietnamese default). Mobile: each row becomes a stacked card.
  • API: reuses /api/hotels/:slug (rooms and final prices) and /api/config; adds GET /api/suggest for the hotel dropdown. Details are in section 18 of the technical design.

Done when: a visitor can add two rows, pick a hotel and room from the dropdowns, see the default final price, overwrite it, see line and grand totals update, reload and find the draft restored, clear it, and print a clean bill with the disclaimer. The base price is never present in any response to the browser.

Phase 5 Mytour crawl with Browser Run Size L · only if Phase 0 approves
  • Job: a weekly cron calls the Browser Run /crawl endpoint for each city listing, with structured JSON output and an include pattern limited to hotel pages. Store the job id; a queue consumer fetches results into mytour_staging.
  • Behaviour to expect: the crawler honours robots.txt and crawl-delay, identifies itself as a bot, and does not bypass bot protection. Disallowed URLs return robots_disallowed; do not work around that.
  • Fallback: Puppeteer or Playwright through a Worker binding, with guardrails limiting the session to mytour.vn, run from a queue with reused sessions.
  • Fields taken: room details per room (type, bed type, size in m², max guests, view, in-room amenities) and the hotel utilities list, grouped. Name, address, stars and coordinates are used for matching, and fill the sheet's empty fields only. Never prices, booking rules, descriptions, photos or reviews. Each value stores its source URL and fetch time.
  • Matching: compare each sheet hotel with Mytour hotels in the same city. Normalise names (no diacritics, drop "khách sạn" or "hotel"), score name, address, phone and coordinates, then auto-link above a high threshold, send the middle band to review, and ignore the rest. Store results in hotel_source_map; confirmed and rejected links are never re-decided.
  • Merge rule: for room details and utilities, Mytour wins once the hotel match is confirmed (or auto-linked above the threshold), and the old sheet value goes to the audit trail. A utility that only the sheet lists is kept as unconfirmed, not deleted. Booking rules, prices, descriptions and photos are never touched. Unmatched Mytour hotels stay review and hidden.
  • Room-type mapping: link each Mytour room to a sheet room in room_type_map by normalised name, bed type and guest count. A Mytour room without a link is shown with "Contact for price". A sheet room without a link stays listed with a review flag. Confirmed links are never re-decided.

Done when: a test crawl of one city fills staging, a labelled sample of about 50 hotels is matched correctly at the chosen thresholds, nothing from Mytour changes booking rules, prices, descriptions or photos, and a Mytour room without a sheet link shows no price.

Phase 6 Admin and review tools Size M · overlaps STORY-7, 8, 9
  • Hidden /admin area (not linked, not in the sitemap or robots.txt, noindex, no-store) with a login page: username and password, server-side sessions, lockout after repeated failures, CSRF protection and an audit trail. Single admin role.
  • First admin created by a one-time script with a generated password shown once in the owner's terminal; the admin must change it at first login.
  • Admin interface in Vietnamese and English. Disclaimer text is editable (both languages required, restore-default button, every version kept in a history table).
  • User management: create, reset password (temporary password shown once), disable and enable; cannot disable yourself or the last active admin.
  • Lockout alerts: when an account is locked after repeated failed logins, send a webhook notification (email optional, later) in addition to the audit entry. The webhook URL and email are set on the config page.
  • Configuration page: service fee percentage (0 to 100) with a price preview, fee note switch, contact phone, Zalo phone, Facebook, email, website, auto-publish, stale-rules days. Every save is audited and refreshes the page cache. Details are in section 17 of the technical design.
  • Review queue: hotels with failed validation and uncertain Mytour matches; approve, edit or reject; edits go into overrides.
  • Sync status: last sync time, hotels per status, errors.
Phase 7 Hardening and release Size M
  • Rate limiting and an admin token on /admin/*; no secrets in wrangler.jsonc vars.
  • Observability: log each sync with counts of created, updated, failed hotels.
  • Run staging first with real sheets; compare counts with the sheets before publishing.
  • Rollback: keep the previous Worker version; hotels can be hidden with one status update.
  • Have the disclaimer, fee note and terms reviewed by a lawyer before launch.

5. Business rules

Final price

fee   = clamp(settings.service_fee_percent, 0, 100)      // default 10
final = round(base * (1 + fee / 100) / 1000) * 1000      // nearest 1,000 VND
// 1,250,000 -> 1,375,000

Disclaimer (every hotel and room)

English: Prices and room availability change with the rooms remaining and hotel reports and are not guaranteed, so please call us to confirm before booking.

Vietnamese: Giá và tình trạng phòng thay đổi theo số phòng còn lại và báo cáo từ khách sạn, chúng tôi không cam kết, vui lòng gọi điện để xác nhận trước khi đặt phòng.

A visible sentence reduces risk but does not guarantee legal protection. Have a lawyer review the wording and consider a short Terms page linked from the footer.

Field ownership

DataSource of truthRule
Room details (type, bed, size, max guests, view, in-room amenities)MytourMytour wins on a confirmed match; the sheet fills gaps
Hotel utilitiesMytourUnion of both lists; sheet-only items kept as unconfirmed
Booking rules (hotel and room level)Excel sheet onlyVerbatim; never touched by the crawler
Base priceExcel sheet onlyService fee added on the server
Descriptions, photos, hotel name, cityExcel sheet onlyMytour is used for matching only
Address, stars, coordinatesExcel sheetMytour fills empty values only; a conflict goes to review

Merge priority

  1. Manual overrides
  2. For room details and utilities: Mytour (confirmed match), then the sheet
  3. For everything else: the Excel sheet, with Mytour filling empty address, stars and coordinates only

Booking rules

Booking rules come only from the Excel sheet, at hotel level and at room level. They are shown verbatim with the date of the last sync. A missing rule shows "Please call to confirm". English text must be a reviewed translation, labelled as such; otherwise the Vietnamese original is shown. The admin page warns when a tab's rules have not changed for a configured number of days.

7. Testing

  • Unit: fee formula and rounding, parser on sample tabs, validation rules, name normalisation and match scoring, i18n dictionary completeness (every key in both languages).
  • Integration: sync of a fixture sheet into a local D1; idempotent rerun; deleted tab; override survives resync.
  • E2E (Playwright): language default and persistence, disclaimer on every card and room, price equals base times 1.10 rounded, unpublished hotels never listed.
  • Matching quality: a labelled sample of about 50 hotels to choose thresholds, measured before enabling auto-link.
  • Booking rules: a crawl never changes booking_rules; a missing rule renders "Please call to confirm"; the text is shown character for character.
  • Room mapping: a Mytour room without a sheet link shows no price; a low-score link waits in review and does not go live.
